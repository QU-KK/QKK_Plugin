Build beautiful Blender panels with Uzima UI

A custom GPU-drawn, web-style interface library for the N-panel and the 3D viewport. Cards, charts, color pickers, curve editors, command palette and more, all wired to real Blender data.

Introduction

Uzima UI is a custom-drawn, web-style user interface library for Blender 5 (it also runs on 4.2 and newer). Every pixel is drawn with Blender's own gpu module: rounded cards, soft shadows, optional gradients, animated controls and a bundled Inter font. Because nothing is a stock Blender widget, you can build panels that look like a modern web app, inside the N-panel and floating above the 3D viewport.

It is not only about looks. Every value widget binds to a real Blender property with undo, buttons and menus run operators, actions get real keymap entries, pickers select real objects and materials, and the curve and color-ramp editors edit real node data.

You can use it three ways:

  • Demo add-on. Install the zip and explore every element on nine pages.
  • Library. Copy the uzima folder into your own add-on and build panels with Python.
  • Generator. Design a panel by drag and drop in your browser and copy the generated Python.

Requirements

Blender5.0 or newer is the target. Works from 4.2 (extension platform).
PythonThe Python that ships with Blender. No pip packages.
GPUAny GPU Blender supports (OpenGL, Vulkan, Metal). Uses GPUShaderCreateInfo.
Operating systemWindows, macOS and Linux.
LicenseThe demo is GPL-3.0-or-later (required for Blender add-ons). The bundled Inter font is under the SIL Open Font License.

Install the demo

  1. Open Preferences. In Blender go to Edit > Preferences > Get Extensions.
  2. Install from disk. Open the small arrow menu at the top right and choose Install from Disk…, then pick uzima_ui_demo-2.0.0.zip. Dragging the zip into Blender works too.
  3. Open the panel. In the 3D viewport press N and click the Uzima tab.
  4. Explore. Use the icon rail on the left to switch pages: Create, Controls, Inputs, Data, Media, Layout, Overlays, Blender, Theme.
Tip
Press Ctrl Shift P for the command palette and Ctrl Shift Q for the pie menu. You can rebind both on the Inputs page.

Quick start

Copy the uzima folder into your add-on, so your package looks like this:

folder layout
my_addon/
├── __init__.py
├── blender_manifest.toml
└── uzima/            <- the library (copy this folder)
    ├── __init__.py
    ├── core.py
    ├── fonts/
    └── ...

Then write your __init__.py:

__init__.py
import bpy
from . import uzima as ui

app = ui.App("my_addon")          # a unique id keeps names from clashing with other add-ons


@app.action("add_lamp", label="Add lamp", icon="light", hotkey="ctrl+shift+L")
def add_lamp(context):
    bpy.ops.object.light_add(type="POINT")


def build(surface):
    return ui.Column(
        ui.Heading("My tool", "Built with Uzima UI"),
        ui.Prop("scene.render.engine"),
        ui.Slider("Exposure", min=-5, max=5, bind="scene.view_settings.exposure"),
        ui.Button("Add lamp", icon="light", action="add_lamp"),
        ui.Button("Add cube", icon="cube", operator="mesh.primitive_cube_add", props={"size": 2}),
    )


app.sidebar("My Tool", build=build)     # a tab in the N-panel
app.viewport()                          # lets windows, dialogs and toasts draw over the 3D view


def register():
    app.register()


def unregister():
    app.unregister()

That is a complete add-on. Enable it, press N and open the My Tool tab.

Note
build(surface) runs the first time the tab is drawn. Call surface.rebuild() to build it again, for example after the scene changes.

How it works

Blender does not let add-ons put custom widgets into the sidebar, so Uzima reserves the space and draws everything itself.

  1. A hidden panel reserves the tab. app.sidebar("My Tool") registers a real Blender Panel with no header. Its height is set to your layout's height, so the sidebar scrolls normally.
  2. A draw handler paints the UI. A POST_PIXEL handler draws the widget tree into that region with one SDF (signed distance field) shader.
  3. A modal operator receives input. A small "pump" operator watches mouse and keyboard over the region and gives events to the widgets. Events no widget wants are passed through, so Blender's own shortcuts keep working.
  4. A timer keeps it alive. A watchdog restarts the pump if Blender cancels it and drives animations.

The widget tree

You build a tree of widget objects. Each frame has three steps: measure (how big do you want to be?), arrange (here is your rectangle) and paint (draw yourself). You rarely touch these unless you write a custom widget.

Units

All sizes are in dp (unscaled pixels). The painter multiplies them by Blender's UI scale, so panels stay crisp and the same size on every monitor.

Surfaces

A Surface is one place the UI draws. app.sidebar() makes a surface in the N-panel. app.viewport() makes a surface that covers the 3D viewport and holds windows, dialogs, drawers, toasts, the command palette and the pie menu. Both are optional.

App and surfaces

Every add-on creates one App. It owns your surfaces, theme, actions and keymap entries.

App

Creates the application object. The id must be unique per add-on and should be a valid Python identifier.

App(id, theme=None, cursors=False)
ArgumentDefaultWhat it does
id—Short name used for panel, operator and keymap names, e.g. "my_addon".
themedefaultA ui.Theme. Pass your own to change colors from the start.
cursorsFalseFalse keeps Blender's arrow everywhere. True switches to a hand over buttons and an I-beam over text fields.

App.sidebar

Adds a tab to the N-panel. Give it either build (a function returning a widget) or root (a ready widget).

app.sidebar(category, build=None, root=None, space="VIEW_3D", theme=None, padding=12)
ArgumentDefaultWhat it does
category—The tab name shown in the sidebar.
buildNonebuild(surface) returns the root widget. Called lazily on first draw.
space"VIEW_3D"Which editor to attach to, for example "IMAGE_EDITOR" or "NODE_EDITOR".
padding12Inner padding of the tab.

App.viewport

Adds the overlay surface to the main viewport region. Needed for app.window, app.dialog, app.toast, app.drawer, app.command_palette, app.pie, app.tour and the viewport tools. Pass build to also draw a permanent widget over the viewport.

app.viewport(space="VIEW_3D", build=None, root=None, theme=None)

App.register / unregister

Call from your add-on's register() and unregister(). Register your own PropertyGroups first, because widgets may bind to them. Both calls are safe to run repeatedly, so disable and enable works.

app.register(); app.unregister()

surface.close_popover()—Close any open popover.

Binding to Blender

A bind connects a widget to a value. Widgets read the value every frame, so they update when something else changes it (the Properties editor, Python, undo). When the user edits the widget, Uzima writes the property and pushes an undo step.

Property paths

The simplest form is a string path that starts from bpy.context:

python
ui.Slider("Samples", min=1, max=4096, integer=True, bind="scene.eevee.taa_render_samples")
ui.Switch("Transparent", bind="scene.render.film_transparent")
ui.Dropdown(bind="scene.render.engine")                       # enum items come from Blender
ui.NumberField("Frame", bind="scene.frame_current")
ui.VectorField("Location", bind="object.location")            # arrays bind as a whole
ui.ColorField("Color", bind="object.color")

When the active object changes, the widget rebinds itself, so object.location always follows the active object.

Bind and FuncBind

Bind

Explicit binding. owner is an object or a function returning one (called each frame).

ui.Bind(owner, attr, index=None, undo=True)
ArgumentDefaultWhat it does
owner—A Blender struct, or lambda: some_object.
attr—Property name.
indexNoneElement of an array property.
undoTruePush an undo step when the user changes the value.
python
ui.Slider("Energy", min=0, max=2000, bind=ui.Bind(lambda: bpy.data.lights["Sun"], "energy"))

Bind.fn

Bind to anything that is not a Blender property: a module variable, a dictionary, a custom property or a calculation.

ui.Bind.fn(getter, setter, label=None)
ArgumentDefaultWhat it does
getter—Function returning the current value.
setter—Function called with the new value.
labelNoneOptional label.
python
state = {"scale": 1.0}
ui.Slider("Scale", min=0.1, max=4,
          bind=ui.Bind.fn(lambda: state["scale"], lambda v: state.update(scale=v)))

Live text, visibility and enabling

python
ui.Label(lambda: f"Selected: {len(bpy.context.selected_objects)}")
ui.Button("Smooth", operator="object.shade_smooth",
          visible=lambda: bpy.context.object is not None,
          enabled=lambda: bpy.context.mode == "OBJECT")

Functions run every frame. Keep them cheap, and avoid creating data inside them.

Forms: apply many edits at once

Wrap widgets in ui.Form and edits are staged. The form shows Revert and Apply buttons, and Apply writes everything as one undo step.

python
ui.Form(
    ui.Prop("scene.render.resolution_x"),
    ui.Prop("scene.render.resolution_y"),
    ui.Prop("scene.render.fps"),
    title="Output", on_apply=lambda: app.toast("Applied", "Render output updated", kind="success"),
)
Heads up
Binding to a property that does not exist raises no error while drawing. The widget shows an empty state instead. Check the Info editor if a widget stays blank.

Actions and hotkeys

An action is a named command. Uzima turns each action into a real Blender operator (<app_id>.uzima_action) and, if you give it a hotkey, a real keymap item. Actions show up in the command palette and can be rebound by the user.

python
@app.action("create", label="Create", icon="sparkle", hotkey="ctrl+shift+C",
            description="Generate something new")
def create(context):
    bpy.ops.mesh.primitive_ico_sphere_add()
    app.toast("Created", "A new ico sphere", kind="success")

# Run it from a button, a menu item, the palette or code:
ui.Button("Create", variant="hero", action="create")
app.run_action("create")

app.action

Register an action. Use it as a decorator or pass fn. The function receives context, or (context, info) when it needs the area and mouse position (to open a pie menu at the cursor).

app.action(name, fn=None, label=None, icon=None, description="", hotkey=None, keymap="3D View", space="VIEW_3D")
ArgumentDefaultWhat it does
hotkeyNoneA string like "ctrl+shift+P", "alt+F" or "shift+ctrl+alt+X".
keymap"3D View"Blender keymap name the hotkey lives in.
space"VIEW_3D"Space type of that keymap.
ArgumentDefaultWhat it does
app.run_action(name, info=None)—Run an action by name.
app.set_hotkey(name, combo)—Change a hotkey at runtime. Blender's keymap updates immediately.
app.hotkey_of(name)—Current hotkey string.
ui.HotkeyField(action=...)—A widget where the user presses a key combination to rebind an action.

Run Blender operators

python
ui.Button("Cube", icon="cube", operator="mesh.primitive_cube_add", props={"size": 2})
ui.MenuItem("Shade smooth", operator="object.shade_smooth")

# from your own callbacks, with a valid area context:
ui.run_operator("mesh.primitive_monkey_add", size=1.5)
ui.run_operator("object.delete", invoke=True)       # INVOKE_DEFAULT (may show a popup)

run_operator finds a suitable area first, so operators that need a 3D viewport work from a sidebar button.

Layout system

Layout is automatic. Column stacks children top to bottom, Row places them side by side, and everything stretches to the available width.

Sizing rules

ArgumentDefaultWhat it does
Default—Children of a Row share the width equally (flex=1).
<code>flex=2</code>—This child gets twice the share of the others.
<code>width=120</code>—A fixed width in dp.
<code>width="auto"</code>—The child keeps its natural size, and the flexible children share what is left.
<code>align="start"</code>—Inside a Column the child does not stretch.
python
ui.Row(
    ui.Button("Preview", icon="eye", variant="outline", width="auto"),   # natural size
    ui.Button("Create", variant="hero", cost=3),                     # takes the rest
    gap=8,
)

ui.Grid(*[ui.Chip(n) for n in names], cols=3)                        # 3 equal columns
ui.Grid(*cards, min_cell=96)                                         # as many columns as fit
ui.Flow(*[ui.Chip(t, removable=True) for t in tags])                 # wraps like text
Tip
A Column inside the N-panel grows to its content and the sidebar scrolls. Use ScrollView (or a Scaffold with a pinned footer) when you want a fixed-height region.

Custom widgets

Subclass ui.Widget. Return a size from measure and draw in paint with the painter. Use self.anim(name, target) for smooth transitions.

python
class Meter(ui.Widget):
    """A horizontal level meter fed by a function."""

    def __init__(self, getter, **kw):
        super().__init__(**kw)
        self.getter = getter

    def measure(self, ctx, avail_w):
        return (avail_w, 28)

    def paint(self, ctx, p):
        x, y, w, h = self.rect
        th = ctx.theme
        v = max(0.0, min(1.0, self.getter()))
        shown = self.anim("level", v)                         # eased toward the target
        p.rect(x, y + h * 0.35, w, h * 0.3, th.surface_0, radius=h * 0.15)
        p.rect(x, y + h * 0.35, w * shown, h * 0.3, th.accent, th.accent_hi, radius=h * 0.15)
        p.text(f"{int(v * 100)}%", x + w, y, size=11, color=th.text_muted, align="right")

    def on_click(self, ctx, ev):
        ctx.app.toast("Meter", "clicked")

ui.Column(Meter(lambda: bpy.context.scene.frame_current / 250))

job = {"progress": 0.0, "running": False}
btn = {}

def start(button):
    btn["render"] = button
    job.update(progress=0.0, running=True)
    button.loading = True
    def tick():
        job["progress"] += 0.05

        app.tag_redraw()
        return 0.1
    bpy.app.timers.register(tick, first_interval=0.1)

Using the Generator

The Uzima Generator is a visual designer that runs in your browser. You build the panel by dragging elements onto a live preview, edit their properties, and copy the Python it writes.

  1. Drag an element from the left list onto the canvas. A line shows where it will land. Drop onto a Card, Row, Column, Grid or Tabs to put it inside.
  2. Click an element to edit its properties on the right: text, icon, variant, ranges, bindings and behavior.
  3. Reorder by dragging elements around the canvas, or use Alt + ↑ / ↓. Del deletes and Ctrl + D duplicates.
  4. Style the preview with the Style button: pick an accent color and switch gradients and shadows on or off, as the library does.
  5. Get code. Open the Code tab. Add-on is a full __init__.py, build() is only the layout function, and JSON is the layout you can save and re-import later.

Troubleshooting

ProblemFix
The tab appears but is empty.Check the Info editor and system console for a Python error inside build(). Errors in build stop the tree from being created.
Windows, dialogs or toasts do not show.Add app.viewport() and make sure the 3D viewport is visible. Overlays draw on that surface.
A widget stays blank.Its bind path may be wrong or the owner is missing (no active object). Use visible= or show an EmptyState.
Text vanished after opening a file.Update to Uzima 2.0 or newer. Fonts are reloaded after every file load.
Colors look washed out in the viewport.Uzima converts colors automatically for the viewport. If you use your own shader, set surface.linear_output = True on viewport surfaces.
Hotkey does nothing.Another add-on or Blender uses it. Choose another or rebind with app.set_hotkey. Hotkeys work with the pointer over the matching editor.
Preview thumbnails are dark.Use files or bpy.types.Image. Non-color images need Image.colorspace_settings.name = "sRGB".
Can't type Chinese, Japanese or Korean.IME composition is not supported in Uzima text fields.
Dragging files in from the desktop does nothing.Blender does not deliver external drops to panels. DropZone opens the file browser instead.

FAQ

Can I use Uzima UI in a commercial add-on?

Yes, if your add-on follows Blender's GPL requirement. The Inter font stays under the SIL OFL, which allows bundling with attribution.

Does it replace Blender's own panels?

No. It adds a tab to the N-panel (or an overlay). You can use Blender's Properties editor next to it. Uzima widgets read and write the same properties.

Does it slow Blender down?

Drawing is batched into a few GPU calls. When nothing animates, Uzima only redraws on demand, and a slow timer keeps idle cost near zero.

Can two add-ons use Uzima at once?

Yes. Each add-on bundles its own copy and creates its own App with a unique id, so panels, operators and keymaps never collide.

Which editors work?

The 3D viewport sidebar and overlay are tested most. space= accepts other editors, such as the Image or Node editor. The image editor and 3D view get automatic linear-color handling.

Can it run in the Properties editor or in popups?

Not at the moment. Uzima draws in sidebars (UI regions) and as an overlay in main windows.
